# App duties

```
duty 10  "Refuse a payee that is Core's own address"
code     packages/sdk/src/payee.ts  payeeProblem(payee, {core, raiser, token}) → "core"
test     packages/sdk/tests/payee.test.ts  "refuses zero and Core, and only flags the raiser and the token"
         tests/e2e/smoke/hand.spec.ts  "a 10% share lands at a pasted address, …; Core's own address is refused"
```

Core proves who signed and who called; everything else that keeps people safe is the app's job. These are the 23 duties the owner's record and Core put on any app (brief 02 §1, R-N are the record's numbers), with the code that meets each and the test that shows it. "Deviation" marks where this build departs from the letter of a duty; each deviation is also a row of [defaults](defaults.md).

This table was written by the docs package from reading the code and test names on 2026-11-20. The `harden-libs` package of the same wave checks the libraries against the same duties; its table in `docs/build-notes/harden-libs.md` is the authority where the two differ.

## Not met, or only partly

- **Duty 8, the wallet's own confirmation**: not met on the one-time-key and new-address paths, on purpose (D-21; left for the owner). **First-seen** is a device time, not an EAS mark (D-25).
- **Duty 17**: only the two-step path ran; an atomic EIP-5792 batch in a real wallet and Multicall3 as the forwarder on a real network were not run.
- **Duty 18**: the SDK supports it; no screen offers it.
- **Duty 12, USDC only**: on the stand the token is `MockUSD`; no USDC address is configured anywhere.
