# Applications

Applications are ordinary protocol participants. aHand does not classify a route participant as a human, application, agent, or service: Core verifies a chain of capabilities and distributes the reward along it. There is no `appId`, no application registry in Core, no application fee, and no fixed position an application must occupy in a route. An application earns only by performing a routing action that survives into the accepted route — the same `Shake` mechanism available to everyone — and a read-only client never has to enter the economic route at all. Opening a page, resolving a name, or querying an index creates no payment claim.

The one built application is the [web app](web-app.md) at https://ahand.in — the reference client for raising, routing, giving, and thanking.

Other applications are possible without any protocol change: domain verticals (for example a lost-and-found client with its own metadata schema and handoff flow) and programmatic Shakers — agents that watch public Hands and forward capabilities toward likely helpers. Neither exists today.
