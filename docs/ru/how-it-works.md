# Как это работает: одна рука, от поднятой до спасибо

Что видит помощник после двух передач (карточка сделки, `apps/hand/src/ui/DealCard.tsx`):

```
✋  Кто-то ищет
    квартиру в Ереване на июнь.

    Награда $40 · открыта до 29 янв

    Поможешь, и тебя поблагодарят      минимум $34
    Передашь дальше                    оставь себе долю, сколько решишь
    Никого не поблагодарят до 29 янв   вся награда вернётся автору
```

Все числа на этой странице взяты из одного прогона на локальном стенде (слот 3, сеть 31337, 2026-11-20; часы этой сети идут на 40 дней вперёд, поэтому даты в ней — декабрь и январь). Это рука номер 14. Каждый шаг выполнен командами, показанными ниже; результаты — в [`../build-notes/docs.md`](../build-notes/docs.md). Тестовый токен — `MockUSD` («тестовые доллары», 6 знаков после запятой); в Base на его месте был бы USDC.

Это перевод страницы [`../how-it-works.md`](../how-it-works.md). Имена Core (Shake, Give, `handId`) не переводятся.

## 1. Поднять руку

Автор (тестовый аккаунт anvil 1, `0x7099…79C8`) пишет заголовок и подробности, ставит награду 40 и оставляет настройки по умолчанию: помощнику остаётся не меньше 70%, рука открыта 30 дней, на каждую выплату — до 250 тысяч газа ([defaults](../defaults.md), D-26).

- Текст приводится к одному виду (NFC, переводы строк LF) и превращается в список утверждений; в сеть уходит только его хеш: `dataHash 0xd647…f06e`. Сами слова в сеть не попадают никогда (`packages/sdk/src/describe.ts`).
- Первый ключ ссылки выводится через HKDF из одного подтверждения аккаунта автора над фиксированным сообщением, с собственным номером руки автора на этом устройстве (`packages/sdk/src/keys.ts`; [links](../links.md)).
- `raise(token, 40000000, expiry, rootKey, 250, 7000, dataHash)` кладёт 40 тестовых долларов в Core. Срок — время последнего блока сети плюс 30 дней (`expiryAfter`), а не часы устройства.

Итог: рука 14, открыта до 2027-01-29 05:32:19 UTC по часам сети, корневой ключ `0x3b12…8EB7`.

В приложении это экран `/raise`; в этом прогоне — `bun tests/e2e/lib/craft.ts make --slot 3 --reward 40 --min-claim 7000 …`, который вызывает те же функции SDK.

## 2. Отправить

Автор отправляет адрес. Он «по ссылке» (так по умолчанию): заголовок стоит до `#`, чтобы мессенджер показал его в превью; подробности, соль и ключ входящих автора едут внутри ссылки после `#`, а эту часть не получает ни один сервер.

```
http://127.0.0.1:18330/31337/14?d=AgFP…#<ссылка>
```

## 3. Две передачи

Первый получатель открывает ссылку и видит карточку сделки: в этот момент «минимум $40» — награда, умноженная на ещё не розданную долю (100%). Он передаёт дальше и оставляет себе 10% на адрес `0x3C44…93BC`. Следующий оставляет себе 5% на `0x90F7…b906`. Каждая передача — это Shake, который подтверждает ключ ссылки прямо на странице, без кошелька и без транзакции; в сеть ничего не уходит.

```sh
bun tools/ahand.ts pass "$ADDRESS" --rpc $RPC --share-bps 1000 --payee 0x3C44CdDdB6a900fa2b585dd299e03d12FA4293BC
bun tools/ahand.ts pass "$NEXT"    --rpc $RPC --share-bps 500  --payee 0x90F79bf6EB2c4f870365E785982E1f101E93b906
```

После второй передачи `bun tools/ahand.ts inspect` показывает: ссылка 383 байта, 922 цифры в QR-коде, адрес 693 символа; путь 100% → 90% → 85%; «passes left: 53 more» — ещё 53 передачи влезут в одно спасибо по худшему газу.

## 4. Ответ

Тот, кто знает квартиру (аккаунт 4, `0x15d3…6A65`), нажимает «Могу помочь». Страница собирает Give на долю, которую оставил путь (85%); его подтверждают последний ключ ссылки и собственный ключ помощника. Прежде чем назвать это ответом, страница спрашивает `checkGive` у Core через `eth_call`; здесь Core вернул хеш `0xf876…892a`. В ответной ссылке нет секрета. Приложение доставляет её на ключ входящих автора через релей (NIP-17), или помощник отправляет её обратно по цепочке.

## 5. Спасибо

Автор открывает ответ, видит, кому сколько, и благодарит. Без сайта:

```sh
bun tools/ahand.ts thank-calldata "$GIVE" --rpc $RPC --out thank.hex    # checkGive у Core, выплаты, худший газ 973 882
bash contracts/exit/ahand.sh thank thank.hex -- --gas-limit 973882 --private-key <аккаунт 1>
```

| Кто | Доля | Выплачено |
|---|---|---|
| первый получатель `0x3C44…93BC` | 10% | 4 тестовых доллара |
| второй получатель `0x90F7…b906` | 5% | 2 тестовых доллара |
| помощник `0x15d3…6A65` | 85% | 34 тестовых доллара |
| всего | | 40 |

Балансы изменились ровно на эти суммы (`cast call balanceOf` до и после). У `hands(14)` выставлен `closedAt`, `thanks(14).giveHash` равен `0xf876…892a`. События квитанции в порядке Core: `Thanked`, `Shaken`, `Paid`, `Shaken`, `Paid`, `Given`, `Paid`.

## 6. Доказательство

```sh
bun tools/ahand.ts verify --rpc $RPC --core $CORE 14
```

23 проверки: 22 сошлись, 1 здесь не проверить (описание: слова едут только в ссылках), 0 не сошлось. Те же проверки с теми же id — на странице паспорта `/31337/14/proof`. Сохранённое через `--save` доказательство проверяется снова командой `verify --bundle`, без сети.

## Если никого не поблагодарили

С секунды окончания срока по часам сети кто угодно может вызвать `refund(14)`, и вся награда вернётся автору. Больше ничто не может забрать деньги из руки ([core](../core.md)).
